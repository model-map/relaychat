# WINSTON Logging & MORGAN Request Tracing – Full Beginner Documentation

Logging is essential for monitoring, debugging, and auditing your application. In this setup:

1. **Winston** handles all application logs with structured JSON output.
2. **winston-daily-rotate-file** rotates log files daily to prevent one huge log file.
3. **Morgan** captures HTTP request details and forwards them to Winston for structured logging.

---

### 1. Installing Dependencies

```bash
npm i winston morgan winston-daily-rotate-file
npm i -D @types/morgan
```

- **`winston`**: Node.js logging library. Supports multiple output targets (“transports”) and structured logs.
- **`winston-daily-rotate-file`**: Automatically creates new log files each day. Prevents log files from growing indefinitely.
- **`morgan`**: HTTP request logger middleware for Express.
- **`@types/morgan`**: TypeScript definitions for Morgan.

### 2. Winston Logger Configuration

**File:** `src/utils/logger.js`

```js
import winston from "winston";
import "winston-daily-rotate-file";
import path from "path";
```

- Import Winston, the daily rotate extension, and Node.js `path` module for cross-platform file paths.

```js
const { combine, timestamp, json, errors } = winston.format;
const LOG_DIR = path.resolve("logs");
```

- **`combine`**: Combines multiple formats (timestamp, json, stack trace).
- **`timestamp`**: Adds a timestamp to each log entry.
- **`json`**: Outputs logs as JSON, suitable for structured logging and machine parsing.
- **`errors`**: Ensures that error stack traces are included in logs.
- **`LOG_DIR`**: Absolute directory where log files will be stored.

```js
const errorFilter = winston.format((info) =>
  info.level === "error" ? info : false
)();
const infoFilter = winston.format((info) =>
  info.level === "info" ? info : false
)();
```

- Filters log messages so that certain transports only receive logs of a specific level (e.g., error logs only).

```js
const rotate = ({ filename, format }) => {
  return new winston.transports.DailyRotateFile({
    dirname: LOG_DIR,
    filename,
    datePattern: "YYYY-MM-DD",
    maxFiles: "14d",
    format,
  });
};
```

- **Helper function** to create a daily rotating log file.
- **`dirname`**: directory to store logs.
- **`filename`**: base filename. `%DATE%` is replaced with current date.
- **`datePattern`**: defines how filenames include dates.
- **`maxFiles`**: keeps logs for 14 days, deletes older files automatically.
- **`format`**: applies structured formatting.

```js
const logger = winston.createLogger({
  level: process.env.LOG_LEVEL || "info",
  format: combine(errors({ stack: true }), timestamp(), json()),
  defaultMeta: { service: "user-service" },
  transports: [
    rotate({
      filename: "combined-%DATE%.log",
      format: combine(errors({ stack: true }), timestamp(), json()),
    }),
    rotate({
      filename: "app-%DATE%-error.log",
      level: "error",
      format: combine(
        errors({ stack: true }),
        errorFilter,
        timestamp(),
        json()
      ),
    }),
    rotate({
      filename: "app-%DATE%-info.log",
      level: "info",
      format: combine(infoFilter, timestamp(), json()),
    }),
    new winston.transports.Console({
      level: "http",
      format: combine(timestamp(), json()),
    }),
  ],
  exceptionHandlers: [
    rotate({
      filename: "app-%DATE%-exceptions.log",
      format: combine(errors({ stack: true }), timestamp(), json()),
    }),
  ],
  rejectionHandlers: [
    rotate({
      filename: "app-%DATE%-rejections.log",
      format: combine(errors({ stack: true }), timestamp(), json()),
    }),
  ],
});
```

#### Key Points:

1. **`level`** – The minimum severity level of logs the logger will record (`info` by default). Levels: `error > warn > info > http > verbose > debug > silly`.
2. **`defaultMeta`** – Adds metadata to every log entry; useful to indicate which service generated the log.
3. **Transports** – Outputs for logs:

   - **Daily rotating files** for combined, error, and info logs.
   - **Console transport** to view logs in the terminal.

4. **Exception & Rejection Handlers** – Catches unhandled errors and promise rejections to prevent silent crashes.

### 3. Morgan Middleware (Winston-backed)

**File:** `src/middleware/morganMiddleware.js`

```js
import morgan from "morgan";
import logger from "../utils/logger.js";
```

- Morgan logs HTTP requests.
- We redirect Morgan logs into Winston to unify all logging.

```js
const morganMiddleware = morgan(
  function (tokens, req, res) {
    return JSON.stringify({
      method: tokens.method(req, res),
      url: tokens.url(req, res),
      status: Number.parseFloat(tokens.status(req, res)),
      content_length: tokens.res(req, res, "content-length"),
      response_time: Number.parseFloat(tokens["response-time"](req, res)),
    });
  },
  {
    stream: {
      write: (message) => {
        const data = JSON.parse(message);
        logger.http("incoming-request", data);
      },
    },
  }
);
```

#### Detailed Explanation:

1. **`tokens.method(req, res)`** – HTTP method of the request (GET, POST, etc.).
2. **`tokens.url(req, res)`** – Requested endpoint.
3. **`tokens.status(req, res)`** – HTTP status code of the response.
4. **`tokens.res(req, res, "content-length")`** – Size of the response.
5. **`tokens["response-time"](req, res)`** – Time taken to respond.
6. **`stream.write`** – Sends the structured log to Winston instead of console.

### 4. Express App Integration

**File:** `src/index.ts`

```ts
import logger from "./utils/logger.js";
import morganMiddleware from "./middleware/morganMiddleware.js";
import express from "express";
import dotenv from "dotenv";
import axios from "axios";

dotenv.config();
const app = express();

// Global middleware for logging HTTP requests
app.use(morganMiddleware);

// Example route
app.get("/test/crypto", async (req, res) => {
  try {
    const response = await axios.get(
      "https://api2.binance.com/api/v3/ticker/24hr"
    );
    res.json(response.data);
  } catch (err) {
    logger.error(err); // application-level errors
    res.status(500).send("Internal server error");
  }
});

// Start server
app.listen(4000, (err) => {
  if (err) {
    console.error("Failed to start server:", err);
    return;
  }
  console.log("Server is running on port 4000");
});
```

**Key Points:**

1. **`app.use(morganMiddleware)`** – All incoming HTTP requests are logged via Morgan → Winston.
2. **Structured logs** – Both HTTP requests and app errors are JSON-formatted.
3. **Error logging** – Any runtime error caught in routes is logged with stack traces for easier debugging.
4. **Separation of concerns** – Winston handles application logging, Morgan handles HTTP request logging, and both integrate seamlessly.
