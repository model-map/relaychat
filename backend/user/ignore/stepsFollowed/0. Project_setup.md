# Project Setup – Full Beginner Documentation

This document explains step-by-step how the backend project is structured, how TypeScript is configured, and why each setup step is necessary. It is written for developers who may be completely new to Node.js, TypeScript, or microservice architecture.
---

## 1. Repository Initialization

1. **Created a Git repository**

   - This allows version control for your project.
   - You can track changes, revert mistakes, and collaborate with others.

2. **Created `backend` and `frontend` folders**

   - Separates server-side code (`backend`) from client-side code (`frontend`).
   - Keeps the project organized.

3. **Inside `backend`, created microservice folders: `chat`, `mail`, and `user`**

   - Each folder represents a **microservice**, i.e., an independent module responsible for a specific domain.
   - This architecture allows scaling services individually, deploying them separately, and reducing interdependency.

## 2. Backend Setup – User Microservice

### 2.1 Initializing Node Project

```bash
npm init -y
```

- Creates a `package.json` file with default values.
- `package.json` tracks dependencies, scripts, and metadata about the project.

---

### 2.2 Setting Up TypeScript

```bash
npx tsc --init
```

This generates a `tsconfig.json` file for TypeScript configuration.

**Important options:**

- `"target": "es2020"`

  - Specifies the JavaScript version output by the TypeScript compiler.
  - `es2020` allows using modern JavaScript features like `async/await`.

- `"module": "nodenext"`

  - Ensures TypeScript understands Node.js module resolution (ESM style).

- `"outDir": "./dist"`

  - Specifies where compiled JavaScript files will be placed.
  - Keeps source code (`src`) separate from compiled output (`dist`).

- `"rootDir": "./src"`

  - Specifies where TypeScript should look for source files.

- `"allowJs": true`

  - Allows JavaScript files to coexist in the project.
  - Useful if you are gradually migrating from JavaScript to TypeScript.

---

### 2.3 Adding Scripts to `package.json`

```json
"scripts": {
  "build": "tsc",
  "start": "node dist/index.js",
  "dev": "concurrently \"tsc -w\" \"nodemon dist/index.js\""
}
```

**Explanation:**

- `"build": "tsc"`

  - Compiles TypeScript into JavaScript files in `dist`.

- `"start": "node dist/index.js"`

  - Runs the compiled server in production.

- `"dev": "concurrently \"tsc -w\" \"nodemon dist/index.js\""`

  - Runs both TypeScript compiler in watch mode (`tsc -w`) and `nodemon` for live-reloading.
  - `concurrently` allows running multiple commands in parallel.
  - This setup ensures that your code automatically recompiles and restarts when changes are made.

---

### 2.4 Installing Dependencies

**Runtime dependencies:**

```bash
npm i mongoose express dotenv
```

- `mongoose` – ODM for MongoDB, manages schemas and models.
- `express` – Node.js web framework, handles HTTP requests and routes.
- `dotenv` – Loads environment variables from `.env` for sensitive data like database credentials.

**Development dependencies:**

```bash
npm i -D @types/mongoose @types/express @types/dotenv concurrently nodemon
```

- `@types/...` – TypeScript type definitions for the respective packages.
- `concurrently` – Runs multiple scripts simultaneously (used for dev workflow).
- `nodemon` – Watches files and restarts the server automatically when changes are detected.

---

### 2.5 Summary of Workflow

1. **Write code in `src/`**
2. **Compile with `npm run build`** → outputs to `dist/`
3. **Run in development:** `npm run dev` (live reload)
4. **Run in production:** `npm run start` (compiled JS only)

This setup ensures a **clean separation between source code and compiled output**, type safety with TypeScript, and a developer-friendly live-reloading workflow.
